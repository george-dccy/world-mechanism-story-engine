# Golden Cases

Golden Cases 用来保护“系统越来越自动，但作品不能越来越像流水线”。

每次修改核心 engine / skill 时，应检查：
- 机制理解是否变浅；
- 是否更快跳到标题和脚本；
- 是否把创意压成固定模板；
- 是否混淆事实与寓言规则；
- 是否丢失作者需要亲自判断的 Gate；
- 是否强迫所有题材都变成同一种“故事”。

## v0.1 三案例基线

### A08｜声音只能留在说话的地方
**科学 / 关系型 / 寓言故事**

测试：
- 科学事实与寓言规则分层；
- 母题先行；
- 重复动作改义；
- 儿童与成人双层阅读。

### H01｜一座城为什么必须共享同一个时间？
**历史 / 技术 / 制度 / 历史故事**

测试：
- 从年份与事件中抽出协调机制；
- 不依赖虚构世界规则；
- 真实制度变化能否成为叙事发动机；
- 事实边界与虚构人物如何共存。

### S01｜如果推荐算法消失七天
**当代社会 / 技术 / 思辨解释**

测试：
- 多方激励；
- 反事实推演；
- 非二元价值判断；
- Expression Router 是否允许“不做故事”。

> A08 已经历多轮人工创作，可作为较强 Golden Case。H01 与 S01 当前为 **Golden Candidates**，需要通过后续实际创作和人工复盘后再升级为锁定 Golden Case。
