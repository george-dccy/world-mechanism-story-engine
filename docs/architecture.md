# Architecture v0.1

## 总原则
> **理解层独立于表达层，表达层独立于生产工具。**

不能让“今天哪个模型最强”“某种画风正火”反向决定我们思考什么、怎么理解、讲什么。

## 六层架构
### A — Question
输入是真实困惑、异常、矛盾、观察或好奇，而不是先做标题。产物：`Question Seed`。

### B — Mechanism
拆 actors、forces、constraints、incentives、flows、feedback loops、thresholds、time scale、information asymmetry、path dependence。产物：`Mechanism Map`。

### C — Research
查事实、原始资料、历史脉络与争议边界，把“事实、解释、假设、寓言”分开。产物：`Evidence Pack`。

### D — Creative
把机制转化为创造性假设：规则改变、极端化、反事实、角色位置互换、时间尺度改变、信息限制、制度改写。产物：`Creative Blueprint`。

### E — Narrative / Explanation
根据 Blueprint 选择故事、解释文、调查、对话、寓言、案例或亲子讨论。产物：`Content Master`。

### F — Renderer / Production
编译为 story-film、minimal-line、whiteboard、archive、evidence+MG、article、comic、talk 或 hybrid。产物：`Production Package`。

## 人工 Gate
1. Question Gate：这真是我想弄明白的问题吗？
2. Mechanism Gate：这个模型让我对世界多理解了一层吗？
3. Creative Gate：创意本身值得看吗，还是只是在包装知识？
4. Release Gate：最终作品是否忠于原始理解？

生产层可以高度自动化，Gate 不默认自动通过。

## GitHub 与 Notion
**GitHub：系统真源。** 保存 engine、schemas、skills、renderer contracts、golden cases、regression checks、architecture decisions。

**Notion：创作者驾驶舱。** 保存问题火花、阅读观察、项目状态、临时研究、Blueprint 工作稿、作品链接和个人复盘。

原则：**Notion 不复制全部规则；GitHub 不吞掉人的思考轨迹。**

## 核心中间语言
Creative Blueprint 是跨媒介稳定接口。只要 Blueprint 仍成立，Renderer 可以随技术变化替换。
